---

## Why

Datenmodell ist die absolute Grundlage. Ohne Schicht-1-Stammdaten (Tenants, Users, Employees, Properties, Property Managers, Contracts, Regions, Service Types, Property Zones) kann nichts anderes aufgesetzt werden. RLS muss von Tag 1 stehen, sonst sind alle nachfolgenden Sicherheits-Annahmen falsch.

## What

PostgreSQL 16 mit RLS Multi-Tenancy, 10 Schicht-1-Tabellen (9 Grunddaten + USERS) + 1 AUDIT_LOG-Tabelle, zwei DB-Rollen (`hmservice_owner`, `hmservice_app`), Extensions, Trigger-Funktionen, Indexes, Drizzle-Kit-Migration-Tracking.

## Constraints

### Must

- PostgreSQL 16+ (Docker-Compose)
- **10 Tabellen:** TENANTS, USERS, EMPLOYEES, PROPERTIES, PROPERTY_ZONES, PROPERTY_MANAGERS, CONTRACTS, REGIONS, SERVICE_TYPES + **AUDIT_LOG**
- RLS auf allen Tabellen mit `TENANT_ID = current_setting('app.current_tenant_id', true)::uuid`
- DB-Rollen: `hmservice_owner` (BYPASSRLS), `hmservice_app` (NOBYPASSRLS)
- Extensions: pgcrypto, pg_trgm, cube, earthdistance
- Trigger `fn_set_updated_at()` auf allen Tabellen mit UPDATED_AT
- Soft-Delete-Pattern: IS_DELETED + DELETED_AT (alle Tabellen außer AUDIT_LOG — Audit ist append-only)
- Audit: CREATED_BY, UPDATED_BY, CREATED_AT, UPDATED_AT
- Partial Indexes mit `WHERE IS_DELETED = FALSE`
- CHECK-Constraint für USERS.ROLE (siehe `docs/ADR-09-users-table-and-roles.md`)
- **Drizzle Kit Migration-Setup** (siehe `docs/ADR-13-migration-tooling.md`): Schema als `0001_schicht1.sql` registriert
- **AUDIT_LOG Append-Only:** GRANT auf `hmservice_app` nur INSERT (kein UPDATE/DELETE) — Compliance-Schutz
- **AUDIT_LOG-Felder:** ID, TENANT_ID, USER_ID (nullable für System-Events), ACTION (Enum), TARGET_TYPE, TARGET_ID, METADATA (JSONB), IP_ADDRESS (inet, nullable), USER_AGENT (text, nullable), CREATED_AT

### Must Not

- Keine Schicht-2/3/4/5-Tabellen in diesem Issue
- Keine Seed-Daten (kommt in ELE-168)
- Keine Auth-Logik (kommt in ELE-169)
- **AUDIT_LOG niemals via UPDATE/DELETE veränderbar** (auch nicht durch Owner — nur Hard-Delete im Recovery-Szenario)
- Keine PII in AUDIT_LOG.METADATA (nur IDs + Action-Typen)

### Out of Scope

- AUDIT_LOG-Auswertungs-API (separates Issue in Wave 4 / DSGVO-Pre-Pilot)
- AUDIT_LOG-Retention-Policy-Implementation (Issue-Definition reicht hier — Cron später)
- Backup-Strategie (siehe ADR-12, eigenes Issue Wave 4)
- Performance-Tuning über Defaults hinaus

  ```sql
  CREATE TABLE AUDIT_LOG (
    ID            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    TENANT_ID     UUID NOT NULL REFERENCES TENANTS(ID),
    USER_ID       UUID,                              -- nullable für System-Events
    ACTION        VARCHAR(50) NOT NULL,              -- z.B. 'employee.read', 'user.login', 'schedule.publish'
    TARGET_TYPE   VARCHAR(50),                       -- z.B. 'employee', 'schedule', 'user'
    TARGET_ID     UUID,                              -- ID des betroffenen Datensatzes
    METADATA      JSONB DEFAULT '{}'::jsonb,         -- zusätzliche Kontext-Daten (keine PII!)
    IP_ADDRESS    INET,
    USER_AGENT    TEXT,
    CREATED_AT    TIMESTAMPTZ DEFAULT NOW() NOT NULL,
    CONSTRAINT CK_AUDIT_LOG_ACTION CHECK (ACTION ~ '^[a-z_]+\.[a-z_]+$')  -- "domain.action" Format
  );
  CREATE INDEX IDX_AUDIT_LOG_TENANT_DATE ON AUDIT_LOG (TENANT_ID, CREATED_AT DESC);
  CREATE INDEX IDX_AUDIT_LOG_USER ON AUDIT_LOG (TENANT_ID, USER_ID, CREATED_AT DESC) WHERE USER_ID IS NOT NULL;
  CREATE INDEX IDX_AUDIT_LOG_TARGET ON AUDIT_LOG (TENANT_ID, TARGET_TYPE, TARGET_ID, CREATED_AT DESC) WHERE TARGET_ID IS NOT NULL;
  ```
