# Wochenplan-Grid-Ansicht (Frontend)

> **Issue:** ELE-180 | **Erstellt:** 2026-05-16 | **Status:** In Progress

## Agent-Pattern

- [ ] Solo
- [ ] Subagent
- [x] **Agent-Team** — Cross-Layer (Design + Data-Layer + UI-Komponenten + Tests). Großer Issue mit /impeccable craft Pre-Design.
- [ ] Parallel-Subagents

**Gewähltes Pattern:** Agent-Team
**Begründung:** 11 Tasks von Design über Hooks bis Tests, ~8-10h. Tief und breit.
**Team-Komposition:** Lead (Opus) + impeccable-Skill für Shape-Phase.

## Why

Das Schulstundenplan-Layout ist DAS Tool für Robert. Zeilen = Mitarbeiter, Spalten = Wochentage, Zellen = Aufgaben farbig nach SERVICE_TYPE. Mit ELE-202 sind echte Demo-Daten da, ELE-180 macht sie sichtbar.

## What

Frontend-Komponente WeekGrid mit 4 Ansichtsmodi, Auslastungsbalken pro MA, Status-Anzeige (DRAFT/PUBLISHED), Publish-Button, KW-Navigation, Plan-Generieren-Button bei leerer Woche.

## Constraints

### Must

- **TanStack Query** für Daten-Fetch (Caching, Invalidation, Loading-States)
- **date-fns** für KW-Berechnung (Frontend bekommt es zugefügt — Backend hat es schon)
- **4 Ansichtsmodi**:
  1. Team-Wochenplan (Default): Zeilen = Mitarbeiter, Spalten = Mo-Fr, Zellen = Entries
  2. Einzel-MA: ein Mitarbeiter über eine Woche (Spalten = Mo-Fr, Zeilen = Stunden)
  3. Tagesansicht: ein Tag über alle Mitarbeiter (Spalten = Mitarbeiter, Zeilen = Stunden)
  4. Objekt-Ansicht: ein Objekt über die Woche (Zeilen = Mitarbeiter, Spalten = Mo-Fr, gefiltert)
- **Service-Type-Color-Coding**: 3px Color-Stripe links an jeder Entry-Card (color_code aus DB)
- **Auslastungs-Balken**: visuell + Zahl ("32h / 40h"), color-coded < 80% / 80-100% / > 100%
- **Vertretungs-Marker**: Badge "vertritt Daniel" bei Entries mit `is_from_reassignment = TRUE`
- **KW-Navigation**: Vorwoche / Heute / Nächste, plus Datum-Range-Anzeige ("KW 21 · 18.-22. Mai 2026")
- **Status-Badge**: DRAFT / PUBLISHED / ARCHIVED, neutrale → grüne → muted Farbe
- **Publish-Button** im Header (nur sichtbar bei DRAFT)
- **Empty-State**: Wenn keine Schedule existiert, "Plan generieren"-Button → ruft `POST /api/schedules/generate`
- **Responsive**: ab 1280px volle Tabelle, darunter Single-Day-Default
- **i18n**: alle Strings via i18next, neue `schedule.json` Namespace

### Must Not

- **Kein Drag&Drop** — kommt in ELE-181
- **Keine Mobile-Detail-Ansicht** — kommt in ELE-182 (hier nur Responsive-Single-Day)
- **Keine Echtzeit-Updates** — Manual Refresh OK für MVP
- **Kein Edit-In-Place** — Read-Only Phase 1

## Tasks

### T1: `/impeccable shape /schedule` — Design-Brief

Discovery-Interview + Design-Brief für Grid-Layout, KW-Navigator-Stil, Entry-Card-Visualisierung, Empty-State.

### T2: Setup TanStack Query + date-fns

- `@tanstack/react-query` + `@tanstack/react-query-devtools` als deps
- `QueryClientProvider` in App.tsx
- `date-fns` als dep (Backend hat schon, Frontend braucht)

### T3: API-Hooks

`src/api/hooks/`:

- `useSchedules({ weekStart })` — listet schedules, gefiltert nach week_start
- `useScheduleEntries(scheduleId)` — alle entries einer Schedule
- `useEmployees()` — aktive Mitarbeiter
- `usePropertiesMap()` — Property-ID → Property-Object Lookup
- `useServiceTypesMap()` — ServiceType-ID → ServiceType-Object Lookup (für Color)
- `usePublishSchedule()` — mutation für POST /api/schedules/:id/publish
- `useGenerateSchedule()` — mutation für POST /api/schedules/generate

### T4: Date-Utils + KW-Navigator

`src/lib/date.ts`:

- `getISOWeekStart(date)` — Montag der KW
- `getCurrentWeekStart()` — heute → Montag
- `addWeeks(date, n)`
- `formatWeekRange(start, locale)` — "KW 21 · 18.-22. Mai 2026"

`src/components/WeekNavigator.tsx`:

- 3 Buttons (Vorwoche / Heute / Nächste) + Range-Anzeige

### T5: Status-Badge + Publish-Button

`src/components/ScheduleStatusBadge.tsx`:

- Status-Map: DRAFT (gray), PUBLISHED (green), ARCHIVED (muted)

`src/components/PublishButton.tsx`:

- Nur visible bei DRAFT
- Trigger `usePublishSchedule()`
- Confirm-Modal vor dem Publish

### T6: WeekGrid Team-View (Default)

`src/components/WeekGrid/WeekGrid.tsx`:

- Grid-Layout: Sticky Sidebar links (Mitarbeiter + Auslastungs-Balken), 5 Spalten Mo-Fr
- Header: KW-Navigator + Status-Badge + View-Mode-Switcher + Publish-Button
- Zellen: Stack von `ScheduleEntryCard`-Komponenten sortiert nach start_time
- Empty-State: "Keine Wochenplanung — Plan generieren?"-Button

`src/components/WeekGrid/ScheduleEntryCard.tsx`:
