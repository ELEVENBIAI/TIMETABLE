## Zusammenfassung

Für die Wochenplanung muss das System wissen, **welche Mitarbeiter welche Aufgaben dürfen** (z.B. nur wer den Winterdienst-Grundkurs gemacht hat, darf Streupflicht übernehmen) und **welches Equipment** sie haben (ein Handrasenmäher braucht doppelt so lange wie ein Aufsitzmäher, das beeinflusst die geplante Dauer). Ohne diese Stammdaten könnten weder die spätere Vertretungs-KI noch die Wochenplan-Generierung sinnvolle Entscheidungen treffen. Bisher waren die Tabellen zwar in der Datenbank, aber niemand konnte sie über die Software pflegen.

Wir haben zwei zentrale Stammdaten-Verwaltungen in der API gebaut: **Qualifikationen** (Code, Name, Beschreibung, "Nachweis erforderlich?"-Flag) und **Equipment-Typen** (Code, Name, eine von sieben Kategorien, ein Stundenaufwand-Faktor zwischen 0.30 und 2.00). Administratoren und Planer können beides anlegen und bearbeiten, alle anderen User dürfen es nur lesen — damit die UI später Auswahl-Listen anzeigen kann. Das Löschen ist doppelt abgesichert: Wenn eine Qualifikation einem Mitarbeiter zugeordnet ist ODER von einer Leistungsart als Voraussetzung verlangt wird, wird das Löschen blockiert. Beim Equipment funktioniert der Block über die Mitarbeiter-Zuordnungen. Außerdem ist der Code pro Tenant einzigartig — ein doppelter Code wird mit einer klaren Fehlermeldung abgelehnt.

Damit ist die Stammdaten-Schicht 2 (Fähigkeiten) für die Pilot-Phase komplett bedienbar. Die Welle-3-Vertretungs-KI (ELE-184/185) kann später direkt auf diese Daten zugreifen, um auszurechnen, wer wann was darf — ohne weitere Datenbank-Eingriffe nötig.
