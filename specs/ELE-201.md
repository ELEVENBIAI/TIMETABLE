# Backend Auth-Endpoints Ergänzung (forgot-password + GET /me)

> **Issue:** ELE-201 | **Erstellt:** 2026-05-17 | **Status:** Todo

## Agent-Pattern

- [x] **Solo** — 2 Routes + Schemas + Tests + Locale-Keys, alles im Backend, klar geschnitten

**Gewähltes Pattern:** Solo
**Begründung:** Zwei kleine Endpoints, klar abgegrenzt. Keine Cross-Layer-Komplexität.
**Team-Komposition:** n/a

## Why

ELE-200 (Frontend Login) braucht zwei Backend-Endpoints, die ELE-170 noch nicht angelegt hat:

- **`POST /api/auth/forgot-password`** — Anti-Enumeration-Stub (immer 200, kein Mail-Send im MVP)
- **`GET /api/users/me`** — Self-Profile-Endpoint für Frontend-Refresh nach Login

Beide klein, gehören zusammen.

## What

- `backend/src/routes/auth.ts` → neue Route `POST /api/auth/forgot-password`
- `backend/src/routes/users.ts` → neue Route `GET /api/users/me`
- Schemas, Locale-Keys, Tests

## Constraints

### Must

- **`POST /api/auth/forgot-password`**:
  - Body: `{ email }` (Zod-validiert)
  - **Immer 200** mit `{ ok: true }` (Anti-Enumeration)
  - Bei existierendem User: Log `action: 'auth.forgot_password_requested', userId, by_ip`
  - Bei unbekannter Email: Log `action: 'auth.forgot_password_unknown_email', emailHash` (kein Klartext)
  - Strengeres Rate-Limit (5/min pro IP) gegen Email-Probing
  - Kein Mail-Versand im MVP (TODO-Comment für Wave 2)
- **`GET /api/users/me`**:
  - Requires Auth (requireAuth preHandler)
  - Returnt aktueller User aus DB via `request.user.userId`
  - Response: `{ id, tenantId, email, displayName, role, isSuperAdmin, locale, mustChangePassword, createdAt }`
  - Soft-deleted User → 401

### Must Not

- Kein echter Mail-Send (Wave 2)
- Keine Password-Reset-Token-Generierung (Wave 2)
- Keine Klartext-Email in Logs (DSGVO)

## Tasks

### T1: `POST /api/auth/forgot-password`

- Zod-Schema `forgotPasswordRequestSchema` in `schemas/auth.ts`
- Route in `routes/auth.ts` (nach login)
- Rate-Limit-Override
- Email-Hash-Helper (SHA-256 truncated)

### T2: `GET /api/users/me`

- Route in `routes/users.ts` (vor /api/users/me/locale)
- Self-Profile-Response-Type

### T3: Tests

- `tests/routes/auth.test.ts`: 4 forgot-password Tests
  - existierender User → 200
  - unbekannte Email → 200 (Anti-Enumeration)

- `tests/routes/users.test.ts`: 3 GET-me Tests
  - ohne JWT → 401
  - mit gültigem JWT → korrekter User
  - mit Token für soft-deleted User → 401
